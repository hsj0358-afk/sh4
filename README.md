# 잃어버린 세계의 지도

1897년의 세계 유적지를 배경으로 한 **모바일 텍스트 TRPG**.
플레이어는 GM이 서술하는 미지의 세계를 탐험하며, 직접 1D20을 굴려 사건을 해결하고
잊힌 문명의 진실을 추적한다.

> 「인류는 처음이 아니었다.」

빌드 도구도 의존성도 없다. 순수 ES 모듈 + Node 표준 라이브러리로만 돌아간다.

```bash
npm start        # http://localhost:5173 (같은 네트워크의 휴대폰에서도 열린다)
npm test         # 규칙 · 콘텐츠 · 플레이 가능성 검사 252개
npm run playtest # 무작위 플레이어 수백 회를 굴려 막다른 길과 난이도를 본다
npm run playtest -- --runs 300 --cautious   # 신중한 플레이어로
npm run playtest -- --runs 300 --golden     # 본줄기를 쫓는 플레이어로
npm run combat-sim  # 전투 균형 — 전략별 결말 분포
npm run bundle      # dist/lost-world-map.html — 파일 하나로 묶는다
```

effect 객체만 서술한다. UI 는 규칙을 모르고 이벤트만 그린다. 새 지역을 추가할 때
건드릴 파일은 `content/episodes/` 하나다.

## 3. 판정 규칙

```
1D20 + 보정 ≥ 목표값        → 성공
목표값 −3 이내로 모자람      → 부분 성공 (대가를 치르고 얻는다)
그 미만                     → 실패
자연 20 / 자연 1            → 목표값과 무관하게 대성공 / 대실패
```

기획서 7-2의 "10~14는 보통·부분 성공" 감각을 유지하면서, 난이도가 다른 판정에도
같은 규칙이 적용되도록 **총합 대비 목표값** 방식으로 일반화했다.

보정치의 출처는 전부 화면에 표시된다.

```
관찰 +4   고고학자 전문 +2   확대경 +2   나디아 하룬 지원 +2
1D20 +10 · 목표값 12
```

- **능력치** — 1~5, 직업별 편향
- **직업 전문** — 직업 태그가 판정 태그와 겹치면 +2
- **장비** — 가장 잘 맞는 **하나만**. 장비를 쌓아 판정을 무너뜨릴 수 없다
- **동료** — 마찬가지로 하나만. 신뢰도가 낮으면 덜 돕고, 부상이면 더 덜 돕는다
- **상태** — 부상 −1 / 중상 −2, 동요 −1 / 공황 −2
- **위험도** — 능력이 아니라 **목표값**을 올린다 (8 이상 +1, 13 이상 +2)
- **불이익의 천장** — 상태 페널티와 위험도 압박의 합은 −4 를 넘지 않는다

마지막 줄이 중요하다. 중상 −2, 공황 −2, 위험도 +2 가 한꺼번에 걸리면 어떤 판정도
통하지 않고, 실패는 다시 상태와 위험도를 악화시킨다. 그 고리에 들어가면 나올 수 없다.
그래서 바닥에서도 손은 남겨 둔다.

### 실패에는 값이 있다

자가진단에서 나온 것: 반복 가능한 판정 27개 **전부**에서 실패의 비용은 시간뿐이었다.
그런데 시간은 위험도를 깎아 준다(6틱마다 −1). 계산해 보면 실패의 실질 위험도가
−0.33 ~ −0.50, 즉 **실패하면 안전해졌다.** 그리고 그 27개 중 26개는 대성공에
단서나 유물이 붙어 있었다.

그래서 최적 전략이 「아무 조사 판정이나 대성공 뜰 때까지 연타」였다. 비용이 없으니까.
판정 63개 중 42개(67%)에서 실패가 시간 말고 아무것도 바꾸지 않았다.

지금은 콘텐츠가 값을 적어 두지 않은 실패에 엔진이 **위험도 +1** 을 붙인다
(`gm.js` 의 `withFailureToll`). 이미 값이 적혀 있는 실패는 건드리지 않는다 —
빈 자리를 메우는 것이지 벌을 두 번 주는 것이 아니다. 위험도가 오르면
`applyEffects` 가 `calm` 을 0 으로 되돌리므로, 실패로 흘려보낸 시간이 추적을
식혀 주던 것도 함께 사라진다.

실측: 위험도 8 이상 도달 60% → 77%, 13 이상 9% → 20%. 완주율은 88.8% → 86.8% 로
거의 그대로다. 밸런스를 흔들지 않고 긴장만 올린다.

### 통찰 — 이 게임의 성장

자가진단 ④: `applyEffects` 에 `stats` 키가 아예 없었다. 능력치는 한 판 내내 불변이고,
보정이 자라는 유일한 축은 장비인데 그것도 「가장 큰 하나만」에 상한 +3.
**3장을 다 돌아도 1장 첫 판정과 성공률이 같았다.** 전투–보상–성장 루프에서
성장 마디가 통째로 비어 있었다.

그렇다고 능력치를 올릴 수는 없다. 3주 만에 사람이 똑똑해지지 않는다.
이 게임에서 자라야 할 것은 **앎**이다.

`content/insight.js` — 단서 두 개가 만나면 통찰 하나가 생기고, 그것이 관계있는
판정에 붙는다. 어디에서도 주지 않는다. 수첩의 두 줄이 만나는 순간 저절로 생긴다.

| 통찰 | 필요한 단서 | 붙는 곳 | 열리는 시점 |
|---|---|---|---|
| 검은 태양의 자리 | 검은 태양 + 별이 떨어진 날 | 신비·공포 +1 | 31% · 36수째 |
| 같은 손 | 측량사의 문체 + 같은 손 | 해독·기록 +1 | 35% · 59수째 |
| 앞서간 사람의 길 | 크레인 원정대 + 총독의 허가 | 잠입·탈출 +1 | 18% · 53수째 |
| 지워진 자리 | 갈대의 경고 + 측량대의 공백 | 방향·이동 +1 | 18% · 90수째 |
| 닫는 일 | 문을 여는 자 + 닫는 사람들 | 사교·정보 +1 | 45% · 84수째 |
| 세는 자의 셈 | 여덟 번째 문 + 세 번째 기록 | 해독·신비 **+2** | 22% · 111수째 |

설계 규칙 셋. 전부 무작위 400판을 굴려 실측하고 정했다.

1. **도달 가능해야 한다.** 조합의 실제 동시 획득률을 재고 골랐다(18~45%).
   아무도 못 만드는 조합은 성장이 아니라 장식이다.
   처음 후보에 넣었던 「어긋난 하늘」은 획득률이 2% 라 버렸다.
2. **시점이 퍼져 있어야 한다.** 36수째부터 111수째까지 사다리로 놓았다.
   전부 마지막 장에 몰리면 자라는 느낌이 안 난다.
3. **태그가 갈려야 한다.** 판정 63개 중 31개가 이미 지식·관찰이다(자가진단 ⑤).
   통찰까지 해독에만 몰리면 고고학자가 또 혼자 자란다. 여섯 통찰이 아홉 태그를 덮는다.

**천장이 있다** — 한 판정에 붙는 통찰의 합은 `MAX_INSIGHT = 3` 을 넘지 않는다.
불이익에 천장(`MAX_PENALTY_STACK`)이 있으면 이익에도 천장이 있어야 한다.
이것이 없으면 단서를 많이 모은 사람의 3장 판정이 전부 자동 성공이 되고,
그러면 성장을 넣은 대가로 긴장을 잃는다.

**칩에 이름이 뜬다.** 「통찰 2가지 +2」가 아니라 「검은 태양의 자리 · 같은 손 +2」다.
왜 이 숫자인가를 항상 확인할 수 있어야 한다는 원칙(기획서 7-3)은 여기에도 적용된다.
통찰 칩만 청록이라, 알아냈을 때 뜬 카드와 같은 색이 다음 판정에서 다시 보인다.

실측 400판 — 판정 카드에 통찰 칩이 실린 비율:

```
제 1 장    2%
제 2 장   19%
제 3 장   33%   ← 곡선이 생겼다
```

판당 평균 1.68가지, 하나도 못 얻는 판이 21%. 완주율은 86.8% → 87.0% 로 그대로다.
성장을 넣되 난이도를 낮추지 않는 것이 목표였다.

**회차로 넘어가지는 않는다.** 도감에는 쌓이지만 다음 판이 통찰을 갖고 시작하지는
않는다. 계승되는 것은 「무엇을 봤는가」이지 「얼마나 유리한가」가 아니다.

### 경쟁자 시계 — 시간을 자원으로

서사는 다섯 번 말했다. "크레인이 앞서간다", "물이 빠지는 계절은 짧다", "우기까지 열흘".
그런데 규칙에는 그 말이 없었다. `state.tick` 을 읽는 곳은 서술의 톤(아침/밤)을 고르는
세 군데뿐이었고, 시간을 써서 잃는 것은 하나도 없었다. **말은 하는데 규칙이 없었다.**

`engine/rival.js` 가 시계 하나를 더 놓는다. 위험도와 다른 종류의 압박이다 —
위험도는 「이 방이 나를 알아챘는가」이고, 이것은 「저 사람이 먼저 도착하는가」다.

- **1틱(30분)마다 +0.5.** 한 장의 실측 소요는 40~69틱(범위 8~147)이다.
  평균적인 탐사는 20~35 에 머물고, 꼼꼼히 훑는 탐사가 문턱에 닿는다.
- **식지 않는다.** 위험도는 조용히 있으면 내려가지만 이것은 안 내려간다.
  내려가면 「기다렸다가 다시 누르기」가 다시 최적이 된다.
- **45 에서 예고한다.** 배신과 같은 원칙 — 뒤통수를 치지 않는다.
- **70 이상에서 장을 마치면** 그가 유물을 먼저 가져간다. 빼앗긴 것이 아니라 늦은 것이라,
  서술도 싸움이 아니라 전보 한 줄로 온다.
- **항로가 출발선을 정한다.** 가장 빠른 배가 0, 나머지는 날수 차이만큼 뒤에서.
  8주짜리 런던 경유가 지하 보관고를 보여 주는 대신 무엇을 내주는지가 여기서 정해진다.
  (여정의 몇 주는 틱으로 흘려보내지 않는다 — 그러면 첫 장면 전에 시계가 꽉 찬다.)
- **크레인과 같은 편이 되면 경주가 끝난다.** 협상 노선이 처음으로 값을 갖는다.
  지금까지 협상은 플래그 하나만 남기고 아무것도 바꾸지 않았다.
- 장이 바뀌면 다시 0 에서 시작한다. 같은 문을 향해 두 배가 다시 떠나는 것이므로.

실측 240판: 급행만 타면 정산 0회, 무작위 항로 9회, 런던 경유만 타면 29회.
「연타하는 사람」 봇은 시계가 92까지 차고 1장에서 죽는다.

### 난이도

한 번 정하면 그 탐사 동안 바뀌지 않는다. 도중에 바꿀 수 있으면 판정의 긴장이 사라진다.

| | 목표값 | 시작 체력·정신 | 받는 피해 |
| --- | --- | --- | --- |
| 기록자 | −1 | +3 | ×0.7 |
| 탐사자 | ±0 | ±0 | ×1 |
| 고고학자의 저주 | +1 | −2 | ×1.35 |

피해 배율이 아무리 낮아도 피해가 0이 되지는 않는다 — 0이 되면 실패가 대가를 잃는다.
무작위 플레이어 200회 기준 챕터 완주율은 각각 100% / 80% / 41%.

### 빛

유적 안의 서술은 전부 램프가 있다는 전제로 쓰여 있다. 그것이 맞다 — 아무도 빛 없이
무덤에 들어가지 않는다. 그런데 규칙에는 그 전제가 없어서, 시장을 건너뛴 사람이
성냥 한 개비로 사천 년 된 쐐기문자를 읽었다.

지하 장면은 `dark: true` 를 갖고, 그곳에서 빛 없이 하는 판정은 **−2** 를 받는다.
막지는 않는다 — 어려울 뿐이고, 그 이유가 판정마다 화면에 뜬다.

다만 준비를 건너뛴 사람을 장 하나 내내 −2 로 묶어 두는 것은, 빛이 중요하다는 것을
알기 전에 내린 선택의 값으로 지나치다. 그래서 **빛 없이 처음 어둠으로 들어서면
곁에 있는 사람이 자기 등불을 하나 내준다** (회차당 한 번). 빌린 등불은 보정이 절반이고
세 번밖에 못 쓴다. 그 차이가 시장에 들르는 이유로 남는다.

### 실패는 벌이 아니다

모든 실패 분기가 `goto`, 피해, 단서, 아이템, 플래그 중 최소 하나를 동반한다는 것을
테스트로 강제한다(`tests/content.test.js`). 벽을 못 열면 대신 바닥 아래에서 빈 공간이 울린다.

## 4. 자유 입력

해석 순서는 좁은 것에서 넓은 것으로 간다.

1. 장면이 직접 정의한 해석기 (`freeform`)
2. 선택지를 말로 부른 경우 (`keys` 대조)
3. 동료 이름 → 관계 장면
4. 소지품 이름 → 사용
5. 전역 행동 사전 (휴식, 수첩, 소지품 확인, 기도, 고함…)
6. 동사별 갈래 (조사·기록 → 기본 판정 / 이동 → 출구 안내 / 대화·은밀·공격 → 각자의 응답)
7. 그래도 못 읽으면 → **그래도 시도한다**

**7번이 이 층에서 가장 중요하다.** 처음에는 여기서 되물었다 —
"조금 더 분명하게. 무엇을 보고, 무엇을 건드릴 것인가?" 그러면 플레이어는 아무것도
하지 못하고 선택지로 돌아가야 한다. **자유 입력이 「다시 고르세요」로 끝나면
그 입력창은 장식이다.**

사람이 GM 일 때는 그 자리에서 되묻지 않는다. 플레이어의 말을 받아 이 자리에서 통하는
판정으로 굴린다. 그래서 그렇게 한다 — 적은 문장을 그대로 행동 줄로 남기고, 장면의
기본 판정으로 결과를 본다. 기본 판정조차 없는 장면이라면 적어도 무엇이 있는지 알려 준다.

```
당신의 행동 — 돌의 모서리부터 정으로 깎는다
돌의 모서리부터 정으로 깎는다.
🎲 탐험 판정  15 + 6 = 21 / 목표 12  성공
모래 아래에 다듬어진 돌이 있다. 계단의 윗단이다.
```

적은 문장을 되돌려 주는 것이 핵심이다. 판정으로 넘기더라도 "무엇을 하는 것으로
읽었는지" 를 먼저 적으면, 잘못 읽었을 때 플레이어가 알아챈다. 엉뚱한 서술을
말없이 내주는 것이 가장 나쁘다.

동사 사전은 넓게 잡는다. 특히 **완력** — 유적에서 사람이 하는 일의 태반이 무언가를
밀고 깎고 걷어내는 것이다. 「깎는다」가 없어서 막다른 길이 된 적이 있다.

정신력이 바닥나면 입력을 한 박자 어긋나게 읽는 오독이 섞인다(기획서 7-7).

## 5. 지도와 로그

**지도**는 두 겹이다. **현장 도면**은 이번 에피소드의 장소 연결도이고, 지상과 지하가
선 하나로 갈린다. 다녀온 곳만 밝혀지고, 다녀온 곳과 이어진 곳은 `미탐사` 점선으로 뜬다.
도면의 높이는 밝혀진 깊이까지만 늘어난다 — 아직 지상뿐이면 지하는 한 뼘만 열려 있다.

**세계 지도**는 1897년의 측량 도면처럼 격자와 적도만 그린다. 유적 후보지는
`소문 → 단서 확보 → 다녀옴` 순으로 승격되고, 짚어내지 못한 곳은 이름 없이 `?` 로 남는다.
에피소드 1을 끝내고 메소포타미아 좌표를 얻으면 동쪽 점 하나에 이름이 붙는다.

새 지역을 추가할 때 `episodes/*.js` 에 `map` 을, `world.js` 에 좌표를 넣으면 된다.
`npm test` 가 지도 노드와 장면의 대응을 검사하므로, 장면을 추가하고 지도에 빠뜨리면 걸린다.

**로그**는 장면 단위 블록으로 쌓인다. 새 장면이 시작되면 이전 장면이 자동으로 접히고,
머리말을 누르면 다시 펼쳐진다. 긴 세션에서도 화면이 한 장면 분량으로 유지된다.

## 6. 전투

기획서 10절 — 턴제, 텍스트 로그, 선택지 기반, 그리고 **전투보다 회피·협상·도주·지형이
중요할 것**. 그래서 적의 체력을 깎는 게임이 아니라, **두 개의 시계**를 굴리는 게임으로 만들었다.

```
전의(resolve)   상대가 이 일을 계속할 의지. 0이 되면 물러난다.
압박(pressure)  당신이 노출된 정도. 꽉 차면 제압당한다.
```

행동은 여섯 가지고, 판정은 전부 기존 1D20 엔진을 그대로 쓴다. 전투만의 주사위 규칙은 없다.

| 행동 | 전의 | 압박 | 비고 |
| --- | --- | --- | --- |
| 공격 | −2 | +1 | 소리가 난다 |
| 엄폐 | — | −4 | 압박에 대한 정답. 전의는 못 깎는다 |
| 지형 이용 | −4 | −2 | 한 번뿐. 통하면 판이 바뀐다 |
| 협상 | −3 | −1 | 전의가 절반 아래일 때만 통한다 (+3) |
| 도주 | — | +1 | 두 번 성공하면 벗어난다 |
| 동료 지원 | −2 | −2 | **판정 없음.** 대신 그가 대신 노출된다 |

### 네 개의 출구, 그중 패배는 없다

`물러남` · `협상` · `도주` · `제압당함`. 넷 다 전투 종료이고, 각각 다른 서사와 다른 대가를 남긴다.
제압당해도 죽지 않는다 — 출구 서술이 "깨어났을 때 가방이 열려 있었다"라고 말하는데
그 직후에 죽으면 게임이 방금 한 말을 스스로 뒤집는 셈이라, 그 피해는 항상 체력 1을 남긴다.
값은 체력이 아니라 **잃은 물건**으로 치른다.

### 균형은 시뮬레이터로 잡는다

`npm run combat-sim` 은 조우 하나를 다섯 가지 정책으로 400번씩 굴린다.
새 조우의 수치를 정할 때 쓰는 도구이고, 보고 싶은 그림이 정해져 있다.

```
[crane_corridor] 전의 9 · 압박한계 10 · 위협 2
  공격 일변도    물러남   4%  협상   0%  도주   0%  제압  96%   평균 4.0R
  공격+엄폐     물러남  29%  협상   0%  도주   0%  제압  71%   평균 9.8R
  지형 우선     물러남  46%  협상   0%  도주   0%  제압  54%   평균 8.4R
  협상 노림     물러남   2%  협상  46%  도주   0%  제압  53%   평균 6.2R
  즉시 도주     물러남   0%  협상   0%  도주  79%  제압  21%   평균 2.9R
```

읽는 법은 이렇다. **공격만 해서는 96% 제압당한다** — 이 줄이 무너지면 엄폐와 지형이
의미를 잃는다. **지형과 협상은 절반쯤 통한다** — 둘 다 살아 있는 길이어야 한다.
**도주는 3라운드에 79%** — 빠르고 확실하되 아무것도 얻지 못한다.

`공격+엄폐`가 9.8라운드까지 늘어지는 것은 남은 흠이다. 그 줄은 최선의 수가 아니고
결국 끝나기는 하므로, 라운드 가속이나 엄폐 체감 같은 장치를 얹지 않았다 —
둘 다 시도해 봤고, 둘 다 "공격만 하기"를 오히려 보상하거나 다른 길을 함께 죽였다.

### 조우를 추가하려면

규칙은 `engine/combat.js` 가 공통으로 갖는다. `content/encounters.js` 에 넣는 것은 문장뿐이다 —
행동 여섯 개의 세 갈래 서술(good/mixed/bad), 상대의 차례 세 단계, 그리고 네 출구.
`npm test` 가 빠진 서술과 갈 곳 없는 출구를 잡는다.

## 7. 캠페인

한 장이 끝나도 탐사자는 초기화되지 않는다. 몸도 마음도 짐도 그대로 다음 배에 오른다.

| 넘어가는 것 | 두고 오는 것 |
| --- | --- |
| 체력 · 정신력 · 소지품 · 유물 | 그 지역의 위험도 |
| 단서 · 동료 · 관계 플래그 | 그 지역의 장면 상태 |

여정 자체가 효과를 갖는다. 이집트에서 바스라까지는 배로 3주. 몸은 그동안 낫고,
본 것은 낫지 않는다 — 그래서 체력은 크게, 정신력은 조금만 회복된다.

**1장의 결과가 2장의 텍스트를 바꾼다.**

- 크레인과 어떻게 헤어졌는가 (`craneAlly` / `craneHasTablet` / `escapedClean`) → 도착 장면과 재대면이 갈린다
- 나디아의 호감도가 4 이상이면 두 강까지 따라온다. 아니면 알렉산드리아에서 내린다
- 핀치가 살아 있으면 습지에도 함께 간다

**두 지역이 만나야 열리는 것이 둘 있다.**

- `not_first`(이집트) + `sumerian_list`(수메르) → 조합 추론 선택지가 열리고,
  성공하면 중심 단서 `처음이 아니었던 것들` 을 얻는다
- `검은 태양의 열쇠`(이집트) + `문의 각인`(수메르) → 두 유물을 맞물릴 수 있다.
  맞물린 순간 그것이 열쇠가 아니라 자물쇠의 절반이었다는 것이 드러난다

**3장의 회랑에서 셋이 만난다.** 이집트의 아래층 문자와 수메르의 왕 목록만으로는 우연을
배제할 수 없다. 세 번째 대륙의 같은 문체가 나와야 추론이 증명이 된다 — 2장의 부분 성공이
"증명하려면 하나가 더 필요하다"고 말했던 그 하나다.

새 에피소드를 추가하려면 `episodes/index.js` 의 `EPISODE_ORDER` 에 넣고,
이전 에피소드의 결말에 `end.next` 를 달면 된다. 나머지는 `campaign.js` 가 처리한다.

### 막간 — 어느 길로 갈 것인가

지역을 통째로 갈라 두 벌씩 쓰는 것은 콘텐츠가 두 배로 드는 일이다. 대신 **캠페인 층에서
가른다.** 같은 목적지로 가되 어느 항로로 가느냐가 시간·몸·아는 것을 서로 다르게 바꾼다
(기획서 18절 '분기형 캠페인').

| 두 강 사이로 | 치르는 것 | 얻는 것 |
| --- | --- | --- |
| 홍해 급행 | 3주, 회복이 얕다 | 크레인보다 앞선다 |
| 정규 항로 | 5주 | 몸도 마음도 제대로 돌아온다 |
| 런던 경유 | 8주, 크레인이 앞선다 | 지하 보관고 — 단서 `the_sealers` 와 프랑스 측량도 |

런던 항로는 `crane_expedition` 단서가 있어야 목록에 뜬다. **조건을 못 채운 항로는
잠긴 채로 보이는 것이 아니라 아예 보이지 않는다** — 못 가는 길을 보여 주는 것은
선택지가 아니라 안내문이다. 고를 것이 하나뿐이면 막간 자체를 건너뛴다.

항로는 `content/interludes.js` 에 있다. 새 에피소드에 막간을 붙이려면 그 파일에
`{ id, label, detail, requires?, text, effects }` 를 두 개 이상 넣으면 된다.

### 신뢰와 배신

지금까지 신뢰도는 판정 보정만 깎았다. 낮아도 불편할 뿐 아무 일도 일어나지 않았고,
그러면 관계를 관리할 이유가 없다. **관계가 수치가 되려면 등을 돌릴 수도 있어야 한다.**

배신은 벌이 아니라 결과다. 그래서 세 가지를 지킨다.

1. **예고된다** — 흔들리기 시작하면 그 순간 로그에 한 줄이 남고, 동행 패널 맨 위에
   경고가 붙는다. 동행 패널을 열어야만 알 수 있으면 그건 예고가 아니라 열람이다.
2. **이유가 있다** — 무엇이 그 사람을 그렇게 만들었는지 문장으로 남는다.
3. **되돌릴 수 있다** — 떠나기 전까지는 회복할 시간이 있고, 회복하면 그것도 알려 준다.

흔들리는 조건은 `신뢰도 ≤ 1 이고 호감도 ≤ 1`. **문턱은 모든 동료의 시작값보다 아래에
둔다** — 크레인은 신뢰도 1로 합류하지만 호감도가 2라 합류하는 순간부터 배신 후보가 되지는
않는다. 배신은 플레이어가 만든 결과여야지 캐릭터에 붙은 태그여서는 안 된다.
(테스트가 모든 동료에 대해 이것을 강제한다.)

검사 시점은 셋. 다음 장으로 떠나기 전(가장 높다), 값나가는 유물을 손에 넣은 직후,
전투 중 지원을 요청했을 때. 결과는 넷 — 조용히 떠남 / 유물을 들고 떠남 / 남아서 파는 쪽
(위험도 +4) / 전투 중 거절(한 턴을 잃는다).

**신뢰가 깎이는 길이 있어야 이 시스템이 작동한다.** 대사 한 줄만으로는 부족해서 두 가지를
규칙에 넣었다.

- **동료를 잃으면 남은 사람들의 신뢰도가 1씩 내려간다.** 다음이 자기 차례일 수 있다고
  생각하는 것은 당연하다.
- **지원 요청은 부르는 때가 곧 판단이다.** 압박이 낮을 때 부르면 신뢰 +1, 이미 무너지는
  판에 부르면 그를 방패로 쓴 것이고 신뢰 −1 이다. 이 분기가 없으면 지원 요청은
  동료를 다치게 하면서 신뢰를 버는 공짜 수단이 된다.

### 회차 계승과 도감

세이브(`save.js`)는 진행 중인 한 판이다. **칸이 셋이다** — 하나로 두면 새 직업을
시험해 보려다 진행 중인 판을 지우게 되고, 이 게임은 한 판이 한 시간짜리라 그 실수의
값이 크다. 자동 저장은 지금 굴리고 있는 칸으로만 간다. 새 판은 빈 칸을 먼저 쓰고,
셋 다 차 있을 때만 무엇을 덮어쓸지 묻는다 (그때도 두 번 눌러야 덮인다).
칸이 하나뿐이던 시절의 세이브는 앱을 켤 때 1번 칸으로 옮겨진다.

아카이브(`archive.js`)는 그 위의 층으로,
여러 판을 가로질러 "이 계정이 지금까지 무엇을 보았는가"를 쌓는다. 표지의 **도감** 버튼과
플레이 중 메뉴에서 열린다.

**계승되는 것은 지식뿐이다.** 능력치도 장비도 넘어가지 않는다. 넘겨주면 회차가 쌓일수록
쉬워지고, 쉬워지면 1897년이 아니게 된다.

- 단서 · 유물 · 결말 · 동행 · 조우 · 지역 · 직업의 수집 진행률
- 본 것은 제목과 내용을, 못 본 것은 남은 개수만. 단서 24개 중 20개가 똑같은 회색 줄로
  늘어서면 도감이 아니라 빈칸 목록이다
- **로그북** — 최근 20회차의 결과. 죽어서 끝난 판도 남는다. 그래야 실패한 회차가
  버려지는 시간이 아니게 된다
- 한 판이 끝나면 이번에 처음 본 것을 로그에 알려 준다

### 결말

마지막 장면 하나가 결말을 정하지 않는다. 세 대륙을 지나오며 무엇을 알아냈고,
누구를 잃지 않았고, 문에 무엇을 했는지가 함께 정한다.

| 결말 | 조건 |
| --- | --- |
| 여덟 번째 문은 닫힌 채로 남았다 | 두 조각을 맞물려 봉인 |
| 문은 안에서 열렸다 | 문을 열었다 |
| 학회는 그것을 정중하게 거절했다 | 문은 건드리지 않고, 증거를 공개 |
| 수첩은 금고에 들어갔다 | 증거는 있으나 공개하지 않음 |
| 당신은 회랑에서 걸어 나왔다 | 그 밖의 모든 경우 |

마지막 줄은 조건 없는 그물이다. 아무것도 증명하지 못한 사람에게도 결말은 있다.
그리고 결말 뒤에는 후일담이 붙는다 — 셋이 걸어 나온 사람과 혼자 걸어 나온 사람이
같은 문장으로 끝나지 않는다.

## 8. 콘텐츠를 추가하려면

`src/content/episodes/` 에 파일 하나를 만들고 `scenes` 를 채운다.

```js
scenes: {
  gate: {
    id: 'gate',
    location: '메소포타미아 · 두 강 사이',
    body: (state) => ['...'],          // 배열 또는 (state) => 배열
    revisitBody: ['...'],              // 재방문 시 (선택)
    onEnter: (state, visits) => ({ danger: 1 }),
    ambientCheck: { ... },             // "주변을 살펴본다" 의 기본 판정
    choices: [
      {
        id: 'push',
        label: '석판을 민다',
        keys: ['민다', '석판'],         // 자유 입력에서 이 선택지를 부르는 말
        requires: { items: ['등반 로프'], clues: ['black_sun'], tags: ['잠입'] },
        once: true,
        check: { stat: '체력', tags: ['완력'], target: 13, prompt: ['...'] },
        outcomes: {
          crit:    { text: ['...'], effects: { clues: ['...'] } },
          success: { text: ['...'], effects: { goto: 'inner' } },
          partial: { text: ['...'], effects: { hp: -2, goto: 'inner' } },
          fail:    { text: ['...'], effects: { danger: 1 } },
          fumble:  { text: ['...'], effects: { hp: -4, san: -2, danger: 2 } },
        },
      },
    ],
    freeform: [{ keys: ['냄새'], text: ['...'], effects: {} }],
  },
}
```

`outcomes` 는 다섯 구간을 다 쓰지 않아도 된다. 빠진 구간은 가장 가까운 것으로 대체된다
(대실패 → 실패, 대성공 → 성공).

**effect 객체**: `hp` `san` `danger` `time` `items` `removeItems` `spend`
`clues` `flags` `companions` `companion` `goto` `end`

`npm test` 가 새 콘텐츠의 장면 참조 · 아이템 이름 · 단서 id · 동료 id · 능력치 이름 ·
도달 가능성 · 실패 분기의 대가 유무를 전부 검사한다. 오타는 테스트에서 걸린다.

## 8.5 배포

개발 중에는 번들러가 없다 — 브라우저가 ES 모듈을 그대로 읽는다. 필요한 건 배포할 때뿐이다.

```bash
npm run bundle            # dist/lost-world-map.html — 열면 바로 돌아가는 파일 하나
npm run bundle:artifact   # <body> 안쪽만 (문서 뼈대를 대신 써 주는 호스트용)
```

모든 모듈을 의존 순서대로 감싸 넣고 `index.html` 과 `styles.css` 를 합친다. 결과는
정적 호스팅 아무 데나 올리거나, 파일로 건네주거나, 더블클릭해서 오프라인으로 열 수 있다.
남는 외부 요청은 Google Fonts 하나뿐이고 — 스타일시트가 이름만 부르고 불러오지는 않던
한글 글꼴이다 — 그것도 못 받으면 시스템 글꼴로 조용히 떨어진다.

정규식으로 `import`/`export` 를 바꾸는 100줄짜리다. 일반적인 번들러라면 파서를 써야 하지만
이 코드베이스가 쓰는 형태는 다섯 가지뿐이고, `tests/bundle.test.js` 가 그것을 고정한다 —
빠진 모듈, 변환하지 못한 구문, 남아 있는 외부 참조를 전부 검사한다.

## 8.7 보고 듣는 것

의존성도 빌드도 없고 배포되는 곳의 보안 정책은 외부 파일을 막는다. 그림도 음악도
넣을 수가 없다. 그래서 **둘 다 그 자리에서 만든다.**

### 장면 그림 (`ui/backdrop.js`)

캔버스에 실루엣 몇 겹을 얹는다. 장소 이름으로 시드를 잡으니 같은 곳은 늘 같은
모습이다. 여덟 종 — 사막·강·시장·지하통로·원형의 방·습지·밀림·항해. 장면의
`location` 에서 자동으로 고르고, 콘텐츠가 `backdrop` 을 직접 지정하면 그것을 쓴다.

**전면 배경이 아니라 장면 머리말 아래 116px 띠다.** 처음에는 화면 전체에 깔았는데,
본문이 그림 위에 겹치니 글자를 읽으려면 본문 뒤에 어두운 판을 깔아야 했고 그 판이
정작 그림을 다 가렸다. 배경이 있다는 것만 알겠고 무엇인지는 안 보이는 상태였다.
띠로 두면 그림은 온전히 보이고 스크롤하면 지나간다 — 읽는 자리를 뺏지 않는다.

구도는 띠 비율(3.4:1)에 맞춰 짰다. 특히 실루엣의 마루는 위쪽에 둔다. 아래쪽에
그리면 하늘이 어두워지는 자리라 형태가 묻힌다.

### 도트 초상 (`ui/sprites.js`)

풍경은 실루엣 몇 겹이면 되지만 사람은 얼굴이 필요하고, 얼굴은 무작위로 만들면
사람처럼 보이지 않는다. 그래서 격자에 직접 찍는다 — 12×14 픽셀, 여섯 색.
각 인물은 문자열 14줄이고 한 글자가 한 픽셀이다.

12픽셀 폭에서는 생김새가 전달되지 않는다. **구별은 머리 모양과 어깨선이 맡는다** —
나디아의 머릿수건, 핀치의 챙 넓은 야전모, 크레인의 중산모. 더 크게 잡으면 그릴 것이
늘어나고 늘어난 만큼 어설퍼진다.

문자열이라 오타가 곧 깨진 그림이므로 `tests/sprites.test.js` 가 폭·높이·기호·색 수를
검사하고, 동료가 늘면 초상이 없다고 실패한다.

### 배경음 (`ui/music.js`)

'곡'이 아니라 '공기'다. 30초 루프는 텍스트 게임에서 세 번째 반복부터 거슬리고,
이 게임은 한 시간씩 읽는 게임이다. 세 겹으로 쌓는다.

| 겹 | 하는 일 |
| --- | --- |
| 드론 | 겹쳐 놓은 저음. 거의 변하지 않는다 — '방의 크기'를 정한다 |
| 결 | 20~40초에 한 번 열리고 닫히는 필터. 숨 쉬는 것처럼 |
| 낱음 | 4~15초에 하나씩, 음계에서 무작위로 — '시간이 흐른다' |

**반복 마디가 없다.** 낱음은 매번 간격을 다시 뽑는다. 평균값으로 `setInterval` 을
걸었더니 정확히 8초마다 소리가 났고, 그건 메트로놈이었다 — 메트로놈이 있으면 마디가
생기고 마디가 생기면 반복이 들린다.

분위기는 장면 종류를 그대로 물려받는다. 조성이 절반을 정한다 — 여행은 D 도리안,
지하는 A 프리지안(반음 부딪침), 원형의 방은 온음음계(어디에도 안 걸린다), 전투는
낱음 대신 심장 박동. 오디오 컨텍스트는 효과음과 하나를 나눠 쓴다.

### 이어하기의 줄거리 요약 (`engine/recap.js`)

며칠 만에 돌아온 사람에게 장면 서술만 다시 보여 주면 "지금 이 방"만 알게 된다.
왜 이 방에 있는지는 상태가 알고 있으므로 거기서 다섯 줄쯤을 만든다 — 몇 번째 장,
지나온 곳, 곁에 있는 사람과 잃은 사람, 가방 속 유물, 마지막으로 적은 단서,
그리고 몸이 성치 않으면 그것도.

장면마다 요약문을 적어 두지 않는다. 콘텐츠가 두 배가 되고 그중 절반은 곧 상태와
어긋난다. 테스트가 "여덟 줄을 넘지 않는다"를 강제한다 — 길면 그것도 읽을 것이 되고,
읽을 것을 하나 더 만들자고 요약을 붙이는 게 아니다.

## 9. 검증

- **252개 테스트** — 주사위 분포, 보정 규칙, 난이도, 상태 클램프, 세션 흐름, 자유 입력,
  전투 규칙, 캠페인 이월, 막간 항로, 신뢰와 배신, 회차 계승, 조사 붙이기, 결말 분기,
  콘텐츠 무결성, 지도 데이터, 그리고 **플레이 가능성**
- **자동 플레이테스트** — 세 장을 이어서 400회, 세 가지 플레이어로
- **전투 시뮬레이터** — 조우별로 다섯 전략을 400회씩

```
캠페인 완주 — 본줄기 89%  /  신중 81%  /  무작위 82%      막힌 세션 0
결말 분포 (본줄기) — 봉인 47% / 개방 33% / 떠남 18% / 보관 2%
전투 결말 — 협상 66% / 제압 28% / 물러남 4% / 도주 2%
```

`--golden` 은 각 장의 본줄기 행동을 우선하는 플레이어다. **이 수치가 `--cautious` 보다
낮으면 설계가 뒤집힌 것이다** — 이야기를 끝까지 읽는 사람이 가장 먼저 쓰러진다는 뜻이니까.
한때 실제로 그랬고(본줄기 0% / 무작위 75%), 그 역전이 아래의 구멍들을 드러냈다.

`--cautious` 는 다치면 쉬고 약을 쓰며, 전투에서는 압박이 차면 엄폐하고 전의가 꺾이면
말을 거는 플레이어를 흉내낸다. 최적 플레이가 아니라 사람이 하는 정도의 판단이다.

전투가 들어오면서 완주율이 74% → 60% 로 내려갔다. 조우가 두 번 생겼고 둘 다 위험하니
당연한 값이다. 다만 그 과정에서 **전투만으로 죽는** 구간이 한 번 나왔고(사망률 19% → 59%),
원인은 압박 시계 위에 체력 피해를 두 번째 치명 시계로 쌓은 것이었다. 피해를 절반으로
낮추고 제압 출구를 비치명으로 만들어 되돌렸다.

### 플레이 가능성 검사

콘텐츠 파일에 선택지를 네 개 적어 두어도 그중 셋이 조건부라면 플레이어는 하나만 본다.
그래서 정적 개수가 아니라 **GM 이 실제로 내주는 개수**를 센다.

- 모든 장면에서, 아무것도 모르는 상태의 8개 직업 전부에게 선택지가 3개 이상 열린다
- 모든 장면에 **나아가는 길**이 있다 — 지금 옮겨 가는 선택지이거나,
  몇 번이고 다시 시도해 잠긴 문을 여는 판정이거나

이 검사가 이미 나가 있던 소프트락 두 개를 잡았다. 왕가의 계곡 야영지와 지구라트 기단에서,
한 번뿐인 조사 판정에 실패하면 진입로를 영영 못 찾는 상태였다. 둘 다 반복 가능한
조사로 바꿨다 — 실패는 시간과 위험도를 물릴 뿐, 길을 없애지 않는다.

### 3장을 붙이며 드러난 것들

세 번째 장을 붙이자 본줄기 완주율이 0% 로 떨어졌다. 원인은 넷이었고, 전부 앞의
두 장에도 있던 것인데 두 장까지는 증상이 나타나지 않았을 뿐이다.

- **얻을 수 없는 물건** — `검은 태양의 열쇠` 는 정의만 되어 있고 아무도 주지 않았다.
  그 물건을 요구하는 「두 유물이 만난다」 선택지와 봉인 결말이 세 커밋 동안 잠겨 있었다.
  테스트는 `applyEffects` 로 물건을 쥐여 준 뒤 검사해서 통과했다. 이제 **요구되는 물건이
  실제로 어딘가에서 나오는지** 를 따로 검사한다. 그 검사가 곧바로 두 번째 고아
  (`의식용 부적`)도 잡았다.
- **한쪽으로만 도는 위험도** — 올라가기만 하고 내려오지 않아서 유적 하나를 훑는 동안
  상한에 닿았고, 닿는 순간 모든 판정이 어려워져 실패가 실패를 불렀다. 눈금을 10 → 16 으로
  넓히고, 조용히 흐른 시간에 가라앉게 하고, 지상으로 물러나면 추적이 끊기게 했다.
- **던전 안의 회복 부재** — 정신력을 깎는 행동은 지하에 몰려 있는데 되찾을 자리는
  밖에만 있었다. 그래서 **읽지 않는 쪽이 유리했다.** 지하 구간마다 「숨을 고른다」를 하나씩 넣었다.
- **바닥에서 못 빠져나오는 상태** — 상태 페널티와 위험도 압박이 합쳐지면 판정이 잠겼다.
  합에 −4 천장을 두었다.

마지막 문 앞에서는 특별히 한 가지를 더 한다. 그 장면은 사람을 죽이지 않는다 —
세 대륙을 걸어온 사람이 문을 만지는 순간 쓰러지면 캠페인 내내 쌓은 결말 분기를 못 본다.
대가는 결말의 문장이 치른다. 정신이 바닥난 채 도착한 사람의 후일담은 이미 다르게 읽힌다.

### 직접 플레이하며 드러난 것들

봇 수백 회로는 잡히지 않는 것들이 있다. 봇은 문장을 읽지 않고, 자유 입력을 적지 않고,
시계를 보지 않는다. 브라우저에서 한 판을 처음부터 굴려 보고 나온 것들이다.

- **쓰이지도 않은 장비가 닳았다.** 목표값 11 짜리 잡담 판정에 보정이 +12 인데
  한 장뿐인 「위조 소개장」이 통째로 소모됐다. 어느 장비가 자동으로 동원될지 플레이어가
  고르지 않으므로, 값은 그 장비가 결과 구간을 실제로 올렸을 때만 치른다.
- **「밀어본다」가 「본다」로 읽혔다.** 조사 동사 사전의 '본다' 가 -어본다로 끝나는 모든
  동사를 삼켰다. 「틈 위의 돌을 밀어본다」가 「계곡 바닥을 파헤친다」가 되어 모래 이야기가
  돌아왔다. **틀린 것보다 나쁜 것은 틀렸다는 표시가 없는 것이다** — 시도 보조용언을 떼서
  본동사를 읽고, 장면의 기본 조사로 흘려보낼 때는 무엇으로 읽었는지 한 줄 적는다.
- **「사진기로 천장을 찍는다」가 거절당했다.** 무엇을 어디에 쓸지까지 다 적은 입력에
  "쓸 자리가 오면 손이 먼저 움직일 것이다" 라고 답했다. 서술을 입은 거절이다.
- **곁에 없는 사람을 불러도 대답이 없었다.** 플레이어는 핀치가 함께 있다고 믿는데
  화면은 그 믿음을 정정하지 않았다.
- **오후 열 시 반에 일출을 봤다.** 시간을 말하는 문장이 고정이었다. 야영도 고정 12틱이라
  아침에 천막을 치고 「새벽 세 시」를 읽었다. 시계를 `src/clock.js` 로 빼고 서술이 시각을
  읽게 했다. 자는 것은 정해진 만큼이 아니라 아침까지다 — 늦게 눕는 쪽이 시간을 덜 쓴다.
- **8주짜리 항로를 고르고 도착했더니 「3주」였다.** 막간이 정하는 것을 도착 장면이 다시
  못 박고 있었다. 이제 테스트가 장 첫 장면의 기간 표기를 막는다.
- **성냥 한 개비로 쐐기문자를 읽었다.** 위의 「빛」 항목. 그리고 빛이 규칙이 되고 나니
  「금속 별들이 **횃불**을 받아 반짝인다」처럼 특정 물건을 못 박은 문장들이 남았다.
  빌린 등불을 든 사람에게는 틀린 문장이라, 전부 「불빛」으로 바꿨다.
- **「불을 켠다」에 대답이 없었다.** 어두운 곳에서 가장 먼저 적게 되는 말인데
  장면 하나에만 핸들러가 있었다. 전역 행동으로 올렸다.

이 중 절반은 테스트를 통과하는 상태였다. 규칙이 맞아도 읽히는 것이 틀릴 수 있고,
그건 플레이해야만 보인다.

### 배신을 붙이며 드러난 것들

배신 규칙을 넣고 나서 무작위 봇 600회를 돌렸더니 **흔들린 회차 23회, 실제 배신 0회**였다.
확률이 낮아서가 아니라 **신뢰가 깎이는 길이 거의 없어서**였다. 콘텐츠 전체에서 신뢰도를
내리는 자리가 두 곳뿐이었고, 그중 호감도까지 함께 내리는 곳은 한 곳이었다.

기능이 있는데 켜지지 않으면 그건 장식이다. 그래서 확률을 올리는 대신 **깎이는 길**을
규칙에 넣었다 — 동료를 잃으면 남은 사람들의 신뢰가 내려가고, 무너지는 판에 지원을
부르면 그를 방패로 쓴 것이 된다(위의 「신뢰와 배신」).

그래도 배신은 드물다. 그것이 맞다 — 아무 잘못도 하지 않은 플레이어가 동료를 잃어서는
안 된다. 대신 **도달 가능하고 눈에 보여야** 한다. 도달 가능성은 테스트가, 눈에 보이는 것은
흔들리는 순간 로그에 남는 한 줄이 맡는다.

`나디아 하룬가 떠났다` — 그 한 줄을 화면에서 보고 조사 처리를 `src/korean.js` 로
분리했다. 받침 유무로 이/가, 은/는, 을/를, 과/와, 으로/로 를 고른다. 코드베이스 전체에서
21곳이 틀리고 있었다.

같은 파일의 `fill()` 이 탐사자 이름을 문장에 넣는다. 콘텐츠가 `'{이름은} 부두에
내려선다.'` 라고 적으면 `gm.js` 의 `asArray` 가 채운다 — 서술이 지나가는 길목이
거기 하나라, 채우는 곳도 하나면 된다. 조사를 자리표 **안에** 넣는 이유는 밖에 두면
치환한 뒤에 다시 고쳐야 하기 때문이다. 안에 두면 채울 때 맞는 조사를 고른다.

이름을 짓게 해 놓고 어디에도 쓰지 않으면 짓지 않은 것과 같다. 그래서 세 장의 도착
장면이 전부 플레이어를 이름으로 부르고(테스트가 강제한다), 이어하기 요약의 첫 줄과
결말의 마지막 줄이 그 이름을 적는다. 생성 화면은 칸을 비워 두지 않는다 —
열 때마다 시대에 맞는 이름을 하나 넣어 두고, ⟳ 로 다시 뽑을 수 있다.
